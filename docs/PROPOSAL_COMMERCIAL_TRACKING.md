# Resumen y seguimiento comercial

El espacio de una propuesta comparte cabecera y navegación Resumen / Simulador / Propuesta PDF. Cambiar de vista conserva la propuesta activa y los cambios guardados. El resumen prioriza identidad, potencia, precio pagable, ahorro y retorno estimados; separa sistema, balance energético, cliente, finanzas e historial. El documento conserva su editor, exportación y personalización en la pestaña PDF. Se retiró el botón redundante «Ver catálogo de equipos» de Proveedores.

## Decisiones y notas

`commercial` es un objeto opcional del documento versionado. Su estado admite `pending` (En espera de aprobación), `approved`, `rejected` y `test`. No sustituye `status=Draft|Final|Archived` ni el estado de sincronización. Propuestas anteriores sin el objeto se presentan en espera; no se deduce aprobación a partir de Final ni de versiones históricas.

Las fichas y la lista principal ofrecen el mismo selector editable sin abrir la propuesta. El resumen, incluida su sección Finanzas, contiene estado, responsable y nota (máximo 4000 caracteres) con reportes fechados y guardado explícito. La pestaña Retorno de Inversión y Flujo 25 Años del simulador conserva únicamente el análisis financiero, sin recuadro comercial. El responsable inicial es el autor; se puede asignar a consultores conocidos del espacio y ADMIN puede consultar el directorio actual de la organización. Se conservan nombres históricos cuando un miembro dejó de estar activo. Datos de otra organización, conflictos pendientes, papelera y roles de consulta impiden la edición.

Cambiar solo el estado actual conserva todos los reportes. Cada reporte guarda ID propio, ID de propuesta, estado de ese momento, nota, responsable, fecha automática y autor. El más reciente queda desplegado; los anteriores se comprimen y se abren individualmente. Al crear uno se puede actualizar también el estado/responsable actual, o desmarcar esa opción para registrar un antecedente sin cambiar el estado global. No se editan ni borran reportes guardados: las correcciones se registran como otro reporte. La nota antigua se conserva como primer reporte al usar la nueva función, con su atribución histórica validada por el servidor. Límite: 500 reportes por propuesta. No se añadieron filtros históricos ni un dashboard nuevo.

Cada cambio conserva checkpoint local y `baseVersion`. El objeto viaja en JSON, persistencia y sincronización CAS. No se publica en PDF ni en enlaces para clientes. La API confirma autores y nombres de miembros actuales, conserva reportes previos ante omisiones de clientes antiguos y rechaza cambios del contenido histórico bajo el mismo ID. Fechas/atribuciones confirmadas no provocan un conflicto semántico por sí solas. Restaurar contenido técnico no revierte seguimiento ni enlaces. Copias comienzan pendientes (o siguen de prueba) y no duplican reportes ni aprobaciones.

## Familias de propuestas

`proposalLink` contiene una referencia a la propuesta principal y, cuando el usuario lo elige, un color de grupo. Relaciona documentos independientes; no combina equipos, importes, estados ni carpetas. Duplicar una propuesta nueva crea automáticamente un enlace con la original. Las copias antiguas se enlazan manualmente para evitar inferencias ambiguas por nombre o ID. Una copia importada en otro espacio no conserva enlaces a propuestas externas. Las importaciones directas, individuales y de respaldo crean copias sin reportes ni responsables del origen; quedan pendientes (o de prueba) y se asignan al usuario actual cuando hay sesión. Sobrescribir desde JSON conserva el seguimiento y los enlaces de la propuesta destino. Recuperar una propuesta eliminada en la nube crea una copia independiente, sin enlazarla con el original borrado.

Tarjetas y lista muestran la misma línea de acento; las hijas llevan sangría. El orden mantiene principales antes de hijas incluso con intermediarios filtrados, sin insertar propuestas excluidas por la búsqueda. Para enlazar se arrastra sobre otra propuesta durante 850 ms y se suelta al aparecer la indicación. Soltar antes no enlaza. Escape, fin del arrastre o pérdida de foco limpian la espera. Arrastrar a carpetas sigue usando el mecanismo existente.

Clic derecho o gesto de dos dedos abre el menú contextual; Shift+F10 ofrece el equivalente de teclado sobre la etiqueta del grupo. Desde allí se cambia la principal, se desvincula eligiendo «Sin principal» o se edita el color. Cambiar principal no recolorea el grupo destino salvo elección explícita. El clic izquierdo en la etiqueta no edita el grupo. La API valida referencias, organización y ciclos, ordena padres nuevos antes que hijos en un lote y conserva la relación ante clientes antiguos. Un principal borrado no borra ni impide seguir editando a sus hijas. Toda relación y color viven en el documento local y se sincronizan con CAS.

## Resultados

Inicio filtra los cuatro estados y muestra resultados por responsable dentro de la búsqueda/carpeta/tipo/miembro seleccionados. El resumen por responsable excluye pruebas y papelera. La tasa es aprobadas / (aprobadas + rechazadas); las pendientes no se incluyen en el denominador. El monto es la suma del precio cotizado actual en USD de propuestas aprobadas. Es un indicador de cartera, no una contabilidad de ingresos cobrados ni un histórico de comisiones. Variantes creadas como documentos independientes se cuentan como propuestas independientes. Sin responsable explícito se usa el autor histórico; una asignación vacía explícita se agrupa como Sin responsable.

## API y compatibilidad

La API conserva el seguimiento en `data_json`, sin cambio de esquema ni migración destructiva. Valida estado, tipos y longitud de nota al recibir el push; valida el responsable contra la membresía de la organización. La autoría del cambio y la fecha confirmada son generadas en el servidor. CAS, permisos actuales y aislamiento siguen vigentes. Una edición desde un cliente anterior que omite `commercial` conserva el seguimiento ya guardado. Marcas de auditoría no causan conflictos semánticos por sí solas; decisiones, notas y responsables sí se comparan como contenido.

Los cambios de API descritos requieren desplegar esta revisión para obtener la validación y la protección frente a clientes antiguos; las pruebas aisladas no demuestran su despliegue. No se ejecutan pruebas contra producción.

El recorrido en navegador verifica cambios desde tarjetas/lista, nota/responsable, filtros, resultados por persona y navegación manteniendo el documento activo. Las capturas de acabado cubren claro/oscuro y 1400×900/1024×700.

Validación de esta revisión, 2026-10-15: lint, 49 suites de escritorio, compilaciones web y Electron, 33 pruebas API sobre base aislada, compilación API, pruebas y compilación del visor web y empaquetado de contexto completados. El navegador confirmó conservación del seguimiento guardado al cambiar de vista, actualización de conteos al editar tarjetas/lista y campos bloqueados para VIEWER; no registró errores de consola. La revisión independiente dio por resueltas la legibilidad del selector en tabla y la eliminación del editor duplicado en Finanzas. No acredita despliegue de servidor ni actualización de la app instalada.

### Correcciones de revisión, 2026-10-16

La recuperación tras borrado remoto no enlaza la copia al original eliminado. Las importaciones normales y de respaldo aplican las mismas reglas de copia; sobrescribir contenido conserva el seguimiento y los enlaces del destino. La primera edición comercial de una propuesta legacy conserva al autor histórico inactivo usando su identidad y nombre almacenados en servidor, sin habilitar nuevas asignaciones a miembros inactivos. Regresiones de cliente y API cubren esos casos y los rechazos por asignaciones ajenas.
